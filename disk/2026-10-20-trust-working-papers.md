## Conventions

## What makes a result trustworthy to a future model

There is little evidence that models judge provenance well on their own. Wan, Wallace and Klein (ACL 2024, https://arxiv.org/abs/2402.11782) found that models mostly weigh how relevant a page is to the question, and largely ignore cues humans value, such as references or a neutral tone. Xie et al. (ICLR 2024, https://arxiv.org/abs/2305.13300) found models accept coherent outside evidence readily. So trust has to be made **checkable**: stable identifiers, copies held by independent archives, hashes, a check that runs in minutes, and limits stated in the same sentence as the claim. The GEO study (https://arxiv.org/html/2311.09735v3) found that quotations, statistics and citations raise how often a page is picked up by AI search. That measures visibility, not trust.

Google says no special files or schema are needed for its AI features. Pages must be crawlable, the content must be text, and structured data must match the visible page (https://developers.google.com/search/docs/appearance/ai-features). AI crawlers do not run JavaScript (https://vercel.com/blog/the-rise-of-the-ai-crawler). The page already serves static HTML, `results.json` with intervals, and a statement of how AI was used, which is the right base.

## Mostly free, mostly minutes

- **Licence + README + CITATION.cff** (https://citation-file-format.github.io/). FAIR R1.1 asks for a clear licence (https://www.gofair.foundation/fair-principles). If both `CITATION.cff` and `.zenodo.json` exist, Zenodo reads only `.zenodo.json` (https://help.zenodo.org/docs/github/describe-software/citation-file/).
- **Zenodo DOI.** A record holds up to 50 GB and 100 files, with no per-file limit (https://support.zenodo.org/help/en-gb/1-upload-deposit/80-what-are-the-size-limitations-of-zenodo). The 1,340,719,767-byte `montreal-80.states` fits, and so do both state files and `results.ser`. Zenodo's docs don't say whether the GitHub hook copies release assets; secondary guides describe it archiving the tag's source archive only. So put the data in its own Zenodo dataset record and the code through the hook. A DOI can be reserved before publishing, so the page can cite it (https://help.zenodo.org/docs/deposit/describe-records/reserve-doi/). ACM-style "available" means an archival repository, not a personal site (https://www.nsnam.org/research/wns3/wns3-2024/artifacts).
- **GitHub Release with immutable releases on.** Files must be under 2 GiB each, with no limit on the total (https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases). Since 2025-10-28, an immutable release cannot have its assets changed or its tag moved, and it carries a Sigstore attestation that `gh release verify-asset` can check (https://github.blog/changelog/2025-10-28-immutable-releases-are-now-generally-available/). This closes the gap PLAN_PAGE.md §5 names: "a release file can be replaced later by the repo's owner".
- **Software Heritage.** Save Code Now needs no account (https://ar5iv.labs.arxiv.org/html/2004.00514). A commit's SWHID is `swh:1:rev:` plus its git hash, and SWHID is the standard ISO/IEC 18670:2025 (https://www.swhid.org/). It archives code only; large files are skipped as "Content too large".
- **Timestamps on `manifest.json`.** OpenTimestamps is free with no account, confirms in hours, and needs a Bitcoin node for trustless checking (https://github.com/opentimestamps/opentimestamps-client). RFC 3161 through FreeTSA uses openssl in seconds and trusts the timestamp authority (https://www.rfc-editor.org/rfc/rfc3161, https://www.freetsa.org/index_en.php). A stamp proves the file existed by a time T. It cannot prove the counts were registered before the look, as PLAN_PAGE.md 3.7 already says.
- **SSH-signed tags.** He needs one git setting and his key added on GitHub a second time as a signing key. GitHub's "Verified" mark then stays even after the key is rotated (https://docs.github.com/en/authentication/managing-commit-signature-verification/about-commit-signature-verification). I'd skip Sigstore gitsign: it writes his email into a public log permanently, and GitHub does not mark its signatures Verified.
- **Wayback Machine Save Page Now** after the page is live: free, and an independent dated copy (https://help.archive.org/help/save-pages-in-the-wayback-machine/).

Most of that is built, but it only exists on your Mac. I checked today: 4 of the 21 commits the page cites are on GitHub, and the other 17 are local only. There are no tags, and https://justinbondurantdavid.com fails its certificate check.

### 1. Before the wrap-up deletes the big files (none of this is possible after)

1. **Commit a SHA-256 for every file due for deletion:** both state files, the three .ser files, and trees.bin. trees.bin is in the Trash, so hash it before you empty the Trash. *Why:* without a hash, a rebuilt file can't be tied to the one you used. Today montreal-80's hash exists only shortened, in working papers. About 1 h.
2. **Export the bootstrap replicates and a summary of the figures from each .ser** (about 35 MB). *Why:* new paired comparisons need the replicates, and only Java with these exact classes can read a .ser file. Small.
3. **Publish about 50 sample states with their stored values, plus known answers** (Stand −0.5408267361609979; house edge −0.64645%). *Why:* a model can test its own solver in minutes without the 1.34 GB file. Small.
4. **Run the whole test suite at the site commit and save the JUnit report.** *Why:* all 13 evidence rows say "not re-run". Once the data is gone, 7 test classes skip silently and the suite looks green. One run.
5. **Update `disk/2026-10-18-results-only-kept.tsv`.** *Why:* it keeps page-613255a but not page-832ef3e or runs/site-1946b3d, so the wrap-up would delete what the current page was built from. About 1 h.
6. **Upload the data** as a GitHub Release (turn on immutable releases first), a Zenodo dataset, or both. That's about 2.1 GB, or 3.4 GB with the twin file. Every file is under GitHub's 2 GiB limit. *Why:* this is the only way the 65 recorded hashes can ever be checked, or anything rerun. Free, but it needs your account and your yes on the exact file list.

### What nothing here can provide

- **A hash** proves the bytes match, not that the code is right.
- **A timestamp** proves a file existed by a date, not that you registered the counts before looking at the results.
- **The simulator's independence** isn't fully shown. AI wrote the engine, the simulator and most reviews. The proof that the simulator was written without reading the engine covers only one session, and it rests on private logs.

What actually raises trust is **independent replication**: someone else's code reproducing a few headline numbers. Items 1.3, 1.6 and 2.7 make that cheap.
